## 1. 目的とビジョン

### 1.1 最終的に目指すもの
U-FRET・楽器.me の代わりになる、**「広告に邪魔されず、そのまま練習まで完結できるコード譜サービス」**。ユーザー投稿型で商用運営する。

| 軸 | 既存サービスの課題 | 本サービスの方針 |
|---|---|---|
| 閲覧体験 | 広告が多い・重い・譜面を遮る | 広告は譜面を遮らない固定枠だけにする。有料プランで広告ゼロ |
| 練習機能 | 閲覧と自動スクロールが中心 | 音源同期スクロール、区間ループ、速度変更、コード音、メトロノーム、練習記録 |

### 1.2 進め方
いきなり公開すると歌詞の権利処理が最初の壁になる。そこで、**まず自分用の練習アプリ（MVP）として作り込み、練習機能の価値を自分で確かめてから公開サービスに広げる**。

MVP の段階から、公開サービスに広げるときに作り直しにならない設計にしておく（→ 5章）。

## 2. フェーズ構成

| フェーズ | 位置づけ | 利用者 | 公開範囲 | 権利処理 | 収益 |
|---|---|---|---|---|---|
| **Phase 1: MVP** | 自分用の練習アプリ | 自分だけ | 非公開 | 不要（私的使用の範囲） | なし |
| **Phase 2: 公開 β** | 投稿・公開の仕組みを追加 | 一般ユーザー（登録制） | 公開 | **必要**（許諾が取れるまでは「コードのみ」公開も選択肢） | なし〜広告 |
| **Phase 3: 商用化** | 収益化・運営体制 | 一般ユーザー | 公開 | 必要 | 控えめ広告＋有料プラン |

### 2.1 各フェーズの前提
| 項目 | Phase 1（MVP） | Phase 2 以降 |
|---|---|---|
| プラットフォーム | Web（スマホ最適化）＋ PWA | 同左（ネイティブアプリは検討外） |
| 対応楽器 | ギター、ピアノ／鍵盤 | ＋ ウクレレ・ベースを検討 |
| 譜面の入手 | 自分で入力・貼り付け | ＋ ユーザー投稿 |
| 使う端末 | PC で入力、スマホ／タブレットで演奏。端末間で同期 | 同左 |
| 開発体制 | 個人開発（＋AI 支援） | 同左（運営負荷次第で見直し） |
| 運用コスト | 無料枠〜月数百円 | アクセス数に応じて |

### 2.2 権利まわり
**Phase 1（MVP）**: 自分で楽しむための複製は私的使用の範囲なので、許諾は不要。ただし次は私的使用を外れやすいため、MVP では作らない。
- 譜面を公開 URL で見られるようにする（共有リンク、公開ページ、検索エンジンへの露出）
- 他人との譜面・アカウントの共有

**外部サイトからの取り込み（→ 4.1 F-EDIT-09〜12）**: 著作権法上は私的使用の範囲に収まるが、**各サイトの利用規約との関係は別問題**なので、リスクを下げた形で作る。
- U-FRET の規約は、スクレイピングを名指しで禁止してはいない。ただし「システムに過度の負担をかける行為」と「通常意図しない効果を及ぼす外部ツールの利用・作成」を禁止している
- 楽器.me は、歌詞・コードデータの印刷・加工・再掲載や、営利目的の利用を禁止している
- 以上を踏まえ、**自分がブラウザで開いている1曲を、自分の操作で取り込む**形に限る。サーバーからの自動取得や一括クロールはしない
- 取り込み元は、許諾を得て公開しているサイトに限る。違法アップロードと知りながら取り込むのは私的使用でも違法になる（著作権法30条1項4号）
- 規約は変わるので、実装前と Phase 2 移行時に原文を確認する

**Phase 2 以降**: 歌詞を公開するには、運営者が JASRAC・NexTone とインタラクティブ配信の利用許諾を結ぶ必要がある。必要になるものは次のとおり。
- 投稿された曲が許諾対象かどうかの照合
- 利用実績（楽曲ごとの閲覧数など）の報告
- 権利者からの削除依頼への対応

許諾の取得には時間がかかる可能性があるため、**Phase 2 の開始時期を決めた時点で、管理団体への相談と専門家（弁護士）への確認を始める**。

**全フェーズ共通**: YouTube は公式の埋め込みプレーヤー（IFrame Player API）のみで使い、音声の抜き出しや広告の除去はしない。

## 3. 利用シーン（MVP）

1. **登録する**: 弾きたい曲の譜面テキストを PC で貼り付ける（またはエディタで耳コピしながら書く）。キー・BPM・参考動画の URL を入れる
2. **下準備する**: 動画を流しながらタップして、譜面の各行がどこで始まるかを記録する（同期データ作り）
3. **弾く**: スマホ／タブレットで曲を開く。動画に合わせて譜面が進む。難しいところはループし、速度を落として練習する
4. **振り返る**: どの曲をどれだけ練習したか見る。セットリストを組んでライブや弾き語りの準備をする

## 4. 機能要求

「フェーズ」列の意味:
- **1-M**: MVP に必須
- **1-S**: MVP 期間中に入れたい
- **1-C**: 余裕があれば MVP 期間中に入れる
- **2** / **3**: そのフェーズで追加する

### 4.1 譜面の登録・編集
| ID | 要求 | フェーズ |
|---|---|---|
| F-EDIT-01 | テキスト貼り付けで取り込む。「コード行＋歌詞行」の2段形式と ChordPro 形式（`[C]歌詞`）を自動判別して変換する | 1-M |
| F-EDIT-02 | テキスト記法で書けるエディタ（プレビューを並べて確認できる） | 1-M |
| F-EDIT-03 | 曲情報（曲名・アーティスト・元キー・カポ・BPM・拍子・参考動画 URL・メモ）の登録 | 1-M |
| F-EDIT-04 | セクション（イントロ・Aメロ・サビなど）の指定 | 1-M |
| F-EDIT-05 | 解釈できないコード表記を警告する | 1-S |
| F-EDIT-06 | 歌詞なしのコード進行だけの譜面（小節区切り）も書ける | 1-S |
| F-EDIT-07 | タップでコードを挿入できる WYSIWYG 編集 | 1-C |
| F-EDIT-08 | 画像／PDF の譜面をテキスト化する | 1-C |
| F-EDIT-09 | **Web ページからの取り込み**: 自分がブラウザで開いているコード譜ページで、ブックマークレット（またはブラウザ拡張）を押すと、その1曲の曲情報・キー・カポ・歌詞・コードを読み取って自分のライブラリに登録する | 1-S |
| F-EDIT-10 | 取り込みはサイトごとの「取り込みアダプタ」で行う。サイトの構造が変わって読めないときは、ページ本文をテキストとして F-EDIT-01 の変換に回す | 1-S |
| F-EDIT-11 | 取り込んだ譜面に、取り込み元の URL・サイト名・取り込み日時を記録する | 1-S |
| F-EDIT-12 | 取り込み後にプレビューを出し、確認・修正してから保存する | 1-S |

外部取り込みで**作らないもの**:
- サーバー側からの自動取得（URL を渡すとサーバーが取りに行く方式）
- 一覧ページやランキングをたどる一括取得
- 定期的な再取得

いずれも運営サイトへの負荷や規約上のリスクが大きく、Phase 2 以降の事業リスクにも直結するため（→ 5章 EX-13、8章）。

- 広告非表示
- 区間ループ・速度変更の無制限利用
- マイリストの無制限
- 練習記録の全期間表示
- 伴奏再生
- オフライン閲覧

「無料でも既存サービスより快適」を満たすことを前提にする。

## 5. 拡張を見据えた設計要件（MVP から守る）

MVP で作る部分でも、Phase 2・3 で作り直しにならないよう次を守る。**MVP では UI に出さなくてよいが、データ構造と処理の境界は最初から用意する**。

| ID | 要件 | 理由（将来の用途） |
|---|---|---|
| EX-01 | すべてのデータに所有者（ユーザー ID）を持たせ、マルチユーザー前提のスキーマにする。MVP の利用者が1人でも同じ構造にする | 一般ユーザーへの開放 |
| EX-02 | 「楽曲」（曲名・アーティスト）と「譜面」（ある人が書いたアレンジ）を別のデータにする。1曲に複数の譜面を持てるようにする | 同じ曲の複数譜面、ランキング、許諾照合 |
| EX-03 | 楽曲に外部 ID（管理団体の作品コードなど）を後から持たせられる余地を残す | 許諾対象の判定、利用実績の報告 |
| EX-04 | 譜面に公開範囲（非公開／限定公開／公開）の項目を持たせる。MVP では「非公開」固定 | 公開機能 |
| EX-05 | 個人設定（移調・カポ・ループ区間など）とお気に入り・セットリストは、譜面本体と分けて「ユーザー × 譜面」単位で持つ | 他人の譜面に自分の設定を持つ |
| EX-06 | 譜面の更新は版として履歴を残す（MVP では最新版だけ表示でよい） | 修正提案、差し戻し |
| EX-07 | 同期データ（タイムスタンプ）は動画 URL と組にして、譜面とは別に持つ。1つの譜面に複数持てるようにする | 動画の差し替え、他ユーザーの同期データの共有 |
| EX-08 | 譜面データはキーに依存しない構造にし、形式を文書化する。ChordPro で入出力できる | 移調、他形式との互換、乗り換え |
| EX-09 | 閲覧・演奏のログを楽曲単位で記録する（MVP では練習記録と兼ねる） | ランキング、利用実績の報告 |
| EX-10 | 認証は外部の認証基盤を使い、一般登録にそのまま広げられる方式にする。MVP は許可リストで自分だけ通す | 会員登録の開放 |
| EX-11 | 画面はサーバー側で描画できる構成にする（MVP は `noindex`） | 公開ページの SEO |
| EX-12 | 機能の出し分け（プラン・権限による有効／無効）を1か所で判定できるようにする | 無料／有料の切り分け、段階的な公開 |
| EX-13 | 外部サイトから取り込んだ譜面には「外部取り込み」の印を付け、**公開範囲を「非公開」以外に変えられない**ようにする。自分で書き直しても印は外さない | Phase 2 で他サイトの譜面が公開コンテンツに混ざるのを防ぐ |
| EX-14 | 取り込みアダプタは本体から切り離し、機能ごと無効化・削除できるようにする | Phase 2 以降で、競合サイトからの取り込み機能を一般ユーザーに提供するかを見直すため |

**MVP で作らないこと（過剰な先回りの防止）**: 公開・投稿の UI、楽曲マスタの整備、課金、広告枠、管理画面。上の設計要件を守るだけにして、機能そのものは Phase 2 以降で作る。

| 法務 | NF-14 | 利用規約、プライバシーポリシー（Cookie・計測の明示） | 2 |
| 法務 | NF-15 | 特定商取引法に基づく表記 | 3 |

## 8. リスク

| リスク | フェーズ | 対策 |
|---|---|---|
| 貼り付けるテキストの形式がばらばらで変換できない | 1 | 変換できない箇所を警告し、エディタですぐ直せるようにする |
| 同期データ作りが面倒で使わなくなる | 1 | タップだけで作れる操作にする。行単位の粗い同期から始める |
| 作り込みすぎて MVP が完成しない | 1 | 1-1 を最短で作り、使いながら優先度を見直す。5章の設計要件は守るが、将来機能は作らない |
| 取り込み元サイトの構造変更で取り込めなくなる | 1〜 | サイトごとのアダプタに閉じ込め、失敗時はテキスト変換に切り替える |
| 取り込み元サイトの規約違反と判断される | 1〜 | 1曲ずつ・自分の操作でのみ取り込み、自動取得・一括取得はしない |
| 他サイトから取り込んだ譜面が公開サービスに混入する | 2 | EX-13 で公開不可にする。Phase 2 では、競合サイトからの取り込み機能を一般ユーザーに出すかを法務確認のうえで判断する（出さない前提で考える） |
| 埋め込み禁止の YouTube 動画がある | 1〜 | 動画 URL を差し替えられるようにし、伴奏再生・メトロノームを代替手段にする |
| 歌詞の許諾が取れない／時間がかかる | 2 | 判断ポイントで早めに相談を始める。取れるまでは「コードのみ」で公開する |
| 公開時に譜面が少ない | 2 | 自分の MVP 期間中の譜面を公開候補にする（許諾範囲内で）。投稿しやすさへの投資 |
| 公開後の運営負荷（モデレーション・障害対応） | 2〜 | マネージドサービス中心の構成、モデレーションの自動化 |
| 広告を控えめにすると収益が足りない | 3 | 有料プランの価値を練習機能で明確にする |

## 9. 用語

| 用語 | 意味 |
|---|---|
| カポ | ギターのフレットを押さえて音程を上げる器具。押さえやすいコード形で弾ける |
| 簡単コード | カポなどで、押さえにくいコード（F などのバレーコード）を減らした表記 |
| 音源同期スクロール | 動画の再生位置に合わせて、譜面の現在位置を自動で追いかける機能 |
| ChordPro | コード譜をテキストで書く記法（例: `[C]歌詞[G]歌詞`） |
| PWA | ホーム画面に追加でき、オフラインでも動く Web アプリ |
| インタラクティブ配信 | ユーザーの求めに応じて著作物をネットで送信すること。歌詞の公開掲載はこれにあたる |
