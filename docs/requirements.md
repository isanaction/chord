# コード譜サービス 要求定義書（v0.1 ドラフト）

最終更新: 2026-09-27
ステータス: ドラフト（「10. 未決事項」の回答をもって v1.0 とする）

---

## 1. 背景と目的

### 1.1 背景
U-FRET・楽器.me に代表されるコード譜サイトは、弾き語り・バンド練習の定番ツールとして広く使われている。一方で、利用者からは次のような不満がある。

- 広告が多く、ページが重い。演奏中に広告で譜面が隠れたりレイアウトがずれたりする
- 「見る」機能はあっても「練習する」機能が弱い（音源に合わせる、区間を繰り返す、コードの響きを確かめる、などができない）

### 1.2 目的
**「広告に邪魔されず、そのまま練習まで完結できるコード譜サービス」** を商用サービスとして立ち上げる。

### 1.3 差別化の軸
| 軸 | 既存サービスの課題 | 本サービスの方針 |
|---|---|---|
| 閲覧体験 | 広告が多い・重い・譜面を遮る | 広告は控えめな固定枠に限定し、譜面エリアには出さない。有料プランで広告を完全に非表示 |
| 練習機能 | 閲覧と自動スクロールが中心 | 音源同期スクロール、区間ループ、速度変更、コード音再生、メトロノーム、練習記録 |

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| サービス形態 | 商用サービス（一般公開・収益化） |
| コンテンツ調達 | ユーザー投稿型 |
| 収益モデル | 控えめ広告＋有料サブスクリプション（広告非表示＋上位機能） |
| プラットフォーム | Web（スマホ最適化のレスポンシブ）。PWA 化を視野に入れる。ネイティブアプリは対象外 |
| 対応楽器（初期） | ギター、ピアノ／鍵盤 |
| 開発体制 | 個人開発（＋AI 支援） |
| リリース目標 | 半年以内（〜2027年3月末）に一般公開 |

### 2.1 最重要制約: 歌詞の著作権
ユーザー投稿型であっても、**歌詞を公開すれば運営者が著作物を配信していることになる**。商用リリースの前提として次が必要になる。

- JASRAC・NexTone とのインタラクティブ配信の利用許諾契約（歌詞掲載）
- 管理団体が扱わない楽曲（非管理楽曲・一部の外国曲など）は掲載できない、または個別に許諾を取る仕組み
- 投稿時に「この楽曲は掲載可能か」を判定するため、許諾対象楽曲の照合（作品コードとの紐付け）
- 利用実績の報告（楽曲ごとの閲覧数など）ができるデータ設計
- 権利者からの削除依頼に対応するフロー

> コード進行そのものは一般に著作物とはみなされにくいが、歌詞は明確に保護対象。契約形態・料率・報告の粒度は管理団体への確認と専門家（弁護士）への相談が必須。**許諾取得のリードタイムがリリース日程のクリティカルパスになりうる**ため、開発と並行して最優先で着手する。

## 3. ステークホルダーとペルソナ

| ペルソナ | 概要 | 主なニーズ |
|---|---|---|
| **閲覧・練習ユーザー（初〜中級）** | 弾き語りしたい曲を検索して弾く。スマホやタブレットを譜面台に置いて使う | 早く見つかる／軽い／広告に邪魔されない／難しいコードを簡単にしたい／原曲に合わせて練習したい |
| **閲覧・練習ユーザー（鍵盤）** | ピアノでコード伴奏したい | 鍵盤でのコード構成音の表示 |
| **投稿ユーザー** | 耳コピした譜面を投稿・修正する | 投稿しやすいエディタ／自分の貢献が評価される |
| **有料ユーザー** | 頻繁に練習する層 | 広告ゼロ／高度な練習機能／オフラインで使える |
| **運営者（自分）** | サービス運営・モデレーション | 不適切投稿の処理／権利処理／利用状況の把握 |
| **権利者・管理団体** | 楽曲の権利を持つ | 適正な許諾・報告／削除依頼への迅速な対応 |

## 4. 機能要求

優先度: **M** = Must（MVP に必須）／ **S** = Should（MVP に入れたい）／ **C** = Could（リリース後）

### 4.1 譜面の閲覧
| ID | 要求 | 優先度 |
|---|---|---|
| F-VIEW-01 | 歌詞とコードを行ごとに揃えて表示する（コードは歌詞の該当位置の上に置く） | M |
| F-VIEW-02 | 曲情報（曲名・アーティスト・キー・カポ推奨・BPM・投稿者）を表示する | M |
| F-VIEW-03 | 登場するコードのダイアグラムを一覧表示する（ギター／鍵盤を切り替え） | M |
| F-VIEW-04 | 文字サイズ変更、表示モード（ライト／ダーク） | M |
| F-VIEW-05 | 1画面に収める表示（段組み・コードのみ表示など）で、演奏中のスクロールを減らす | S |
| F-VIEW-06 | 印刷／PDF 出力 | C |
| F-VIEW-07 | セクション（Aメロ・サビなど）の見出し表示と、そこへのジャンプ | S |

### 4.2 演奏支援（基本）
| ID | 要求 | 優先度 |
|---|---|---|
| F-PLAY-01 | 自動スクロール（速度調整、一時停止、タップで再開） | M |
| F-PLAY-02 | 移調（±半音単位。♯／♭表記はキーに応じて自動選択） | M |
| F-PLAY-03 | カポ設定（カポ位置に応じて表示コードを変換） | M |
| F-PLAY-04 | 簡単コード変換（押さえにくいコードが少なくなるカポ位置を提案） | M |
| F-PLAY-05 | コード表記の簡略化（例: テンションを省いたコードで表示） | S |
| F-PLAY-06 | 演奏中の画面スリープを防ぐ（Wake Lock） | M |

### 4.3 練習機能（差別化の中心）
| ID | 要求 | 優先度 |
|---|---|---|
| F-PRAC-01 | **音源同期スクロール**: 楽曲に紐づけた YouTube 動画を埋め込み、再生位置に合わせて譜面の現在位置をハイライト・スクロールする | M |
| F-PRAC-02 | 同期データ（小節・行ごとのタイムスタンプ）を作成・修正するエディタ（再生しながらタップで打てる） | M |
| F-PRAC-03 | 区間ループ（A–B 区間を指定して繰り返す。セクション単位でも指定できる） | M |
| F-PRAC-04 | 再生速度変更（0.5〜1.0 倍など。YouTube プレイヤーが対応する範囲） | M |
| F-PRAC-05 | コード音の再生（ダイアグラムやコード名をタップすると鳴る。ギター／ピアノ音色） | M |
| F-PRAC-06 | メトロノーム（BPM・拍子を指定。曲の BPM を初期値にする） | M |
| F-PRAC-07 | コード進行の伴奏再生（BPM に合わせてコードを鳴らし、音源なしで練習できる） | S |
| F-PRAC-08 | カウントイン | S |

### 4.4 練習管理・マイリスト
| ID | 要求 | 優先度 |
|---|---|---|
| F-LIB-01 | お気に入り登録 | M |
| F-LIB-02 | マイリスト（セットリスト）の作成・並べ替え | M |
| F-LIB-03 | 曲ごとの個人設定の保存（移調・カポ・スクロール速度・ループ区間） | M |
| F-LIB-04 | 練習記録（練習した日時・時間・曲。カレンダーや連続日数で表示） | S |
| F-LIB-05 | 苦手コードの登録と、それを含む曲の把握 | C |
| F-LIB-06 | 閲覧履歴 | M |

### 4.5 検索・発見
| ID | 要求 | 優先度 |
|---|---|---|
| F-SRCH-01 | 曲名・アーティスト名で検索（ひらがな・カタカナ・ローマ字の揺れを吸収する） | M |
| F-SRCH-02 | アーティストページ（曲一覧） | M |
| F-SRCH-03 | ランキング（デイリー・ウィークリー） | M |
| F-SRCH-04 | 難易度・キー・使用コードでの絞り込み（例: 「F を使わない曲」） | S |
| F-SRCH-05 | 新着・更新された譜面 | S |

### 4.6 投稿・編集（ユーザー投稿型の中核）
| ID | 要求 | 優先度 |
|---|---|---|
| F-POST-01 | 譜面エディタ（歌詞にコードを置く WYSIWYG と、テキスト記法の両方で編集できる） | M |
| F-POST-02 | テキスト記法は ChordPro 互換を基本にし、内部データはキー非依存（度数で扱えるなど移調しやすい）構造にする | M |
| F-POST-03 | プレビュー、下書き保存 | M |
| F-POST-04 | 楽曲マスタとの紐付け（曲名・アーティストを候補から選ぶ。許諾対象かどうかの判定に使う） | M |
| F-POST-05 | 許諾範囲外の楽曲は、歌詞なし（コード進行のみ）でしか投稿できない | M |
| F-POST-06 | 同じ曲に複数の譜面を許し、評価の高い版を既定表示にする | S |
| F-POST-07 | 他ユーザーからの修正提案（差分表示）と、投稿者による採用 | S |
| F-POST-08 | 版履歴と差し戻し | S |
| F-POST-09 | 譜面の評価（役に立った／正確さ） | S |
| F-POST-10 | 投稿者プロフィールと貢献実績の表示 | C |

|---|---|---|
| F-ACCT-01 | 会員登録なしでも閲覧・基本演奏支援は使える | M |
| F-ACCT-02 | 会員登録・ログイン（メール＋ソーシャルログイン） | M |
| F-ACCT-03 | 有料プランの購読・解約・支払い方法の変更（Web 決済） | M |

### 4.8 無料プランと有料プランの切り分け（案）
| 機能 | 未登録 | 無料会員 | 有料会員 |
|---|---|---|---|
| 閲覧・移調・カポ・自動スクロール・ダイアグラム | ○ | ○ | ○ |
| コード音再生・メトロノーム | ○ | ○ | ○ |
| 音源同期スクロール（基本） | ○ | ○ | ○ |
| 区間ループ・速度変更 | － | 回数や曲数に上限 | ○ |
| お気に入り・マイリスト | － | 上限あり | 無制限 |
| 曲ごとの個人設定の保存 | － | ○ | ○ |
| 練習記録 | － | 直近のみ | 全期間・統計 |
| 伴奏再生 | － | － | ○ |
| オフライン閲覧（PWA） | － | － | ○ |
| 広告 | 控えめ | 控えめ | なし |

> 無料の範囲を狭くしすぎると集客で既存サービスに勝てない。**「無料でも既存サービスより快適」を満たしたうえで、練習を続ける人が払いたくなる線引き**にする。

### 4.9 広告
| ID | 要求 | 優先度 |
|---|---|---|
| F-AD-01 | 広告枠はあらかじめ決めた位置のみ（譜面の上下など）。譜面エリア・操作ボタンと重ねない | M |
| F-AD-02 | 全画面広告・ポップアップ・自動再生動画広告は使わない | M |
| F-AD-03 | 広告の読み込みでレイアウトがずれない（枠のサイズを先に確保する） | M |
| F-AD-04 | 演奏モード（自動スクロール・同期再生中）は広告を最小化または非表示にする | S |

|---|---|---|
| F-OPS-01 | 通報機能（誤り・不適切・権利侵害） | M |
| F-OPS-02 | 権利者からの削除依頼の窓口と、非公開化・削除の処理 | M |
| F-OPS-03 | 管理画面（投稿の非公開化・ユーザー停止・楽曲マスタの管理） | M |
| F-OPS-04 | 管理団体への利用実績報告データ（楽曲ごとの閲覧数など）の集計・出力 | M |
| F-OPS-05 | スパム・荒らし対策（レート制限、新規ユーザーの投稿制限など） | M |

## 5. 非機能要求

### 5.1 パフォーマンス（「重い」への回答）
| ID | 要求 |
|---|---|
| NF-PERF-01 | 譜面ページの LCP 2.5 秒以内（モバイル・4G 相当、p75） |
| NF-PERF-02 | CLS 0.1 未満（広告を含めて） |
| NF-PERF-03 | INP 200ms 以内。移調・カポ変更はサーバーに問い合わせず端末内で即座に反映する |
| NF-PERF-04 | 譜面ページの初期転送量の上限を決めて守る（目安 300KB 以内、広告を除く） |
| NF-PERF-05 | 音源同期のずれ ±100ms 以内（体感で違和感がない範囲） |

### 5.2 SEO・流入
| ID | 要求 |
|---|---|
| NF-SEO-01 | 譜面・アーティストページはサーバー側で描画し、検索エンジンにインデックスされる（コード譜サイトの主な流入は「曲名 コード」の検索） |
| NF-SEO-02 | 構造化データ、OGP、適切なページタイトルを出す |
| NF-SEO-03 | 恒久的で読みやすい URL |

### 5.3 可用性・拡張性
| ID | 要求 |
|---|---|
| NF-AVL-01 | 稼働率 99.5% 以上（個人運営を前提に、マネージドサービス中心で構成する） |
| NF-AVL-02 | 閲覧はキャッシュ（CDN）で処理し、アクセス急増（テレビ放映・ヒット曲の発生）に耐える |
| NF-AVL-03 | 運用コストがアクセス数に比例しすぎない構成にする |

### 5.4 セキュリティ・プライバシー
| ID | 要求 |
|---|---|
| NF-SEC-01 | 決済情報は自前で持たない（決済代行サービスに任せる） |
| NF-SEC-02 | 投稿内容の XSS 対策（エディタ入力は構造化データとして保存し、表示時にエスケープする） |
| NF-SEC-03 | 個人情報保護法に沿ったプライバシーポリシー。広告・計測のための Cookie 利用を明示する |
| NF-SEC-04 | 認証まわりはブルートフォース対策・レート制限を入れる |

### 5.5 ユーザビリティ・アクセシビリティ
| ID | 要求 |
|---|---|
| NF-UX-01 | スマホ縦・横、タブレット（譜面台に置く想定）、PC で快適に使える |
| NF-UX-02 | 演奏中は大きなタップ領域で操作できる（片手・指先が濡れていても押せる程度） |
| NF-UX-03 | WCAG 2.2 AA を目安（コントラスト、キーボード操作） |
| NF-UX-04 | 対応ブラウザ: iOS Safari／Android Chrome の最新2版、PC の主要ブラウザ最新版 |

### 5.6 法務・規約
| ID | 要求 |
|---|---|
| NF-LEG-01 | 利用規約（投稿コンテンツの権利帰属・運営者への利用許諾・禁止事項） |
| NF-LEG-02 | 特定商取引法に基づく表記（有料プラン提供のため） |
| NF-LEG-03 | YouTube 埋め込みは公式の埋め込みプレーヤー（IFrame Player API）のみを使い、YouTube の利用規約に従う（音声の抜き出し・広告の除去はしない） |
| NF-LEG-04 | 削除依頼への対応手順（情報流通プラットフォーム対処法などの動向も確認する） |

## 8. 主要リスク

| リスク | 影響 | 対策 |
|---|---|---|
| 歌詞掲載の許諾が取れない／想定より時間がかかる | リリース不可・延期 | 最優先で着手。取れるまでは「コードのみ」で公開する選択肢を用意 |
| **コンテンツ不足（立ち上がりで譜面がない）** | 検索流入が伸びず投稿者も集まらない | 定番曲を運営で先に用意する、投稿しやすさへの投資、投稿者の貢献の見える化 |
| 譜面の品質が低い | 「不正確」という評判が広がる | 評価・修正提案・版管理、同期データで検証しやすくする |
| YouTube の埋め込み不可の動画・仕様変更 | 同期機能が使えない曲が出る | 同期データを動画と切り離して持ち、動画を差し替えられるようにする。伴奏再生を代替手段にする |
| 個人開発で運用負荷が高い | 障害対応・モデレーションが回らない | マネージドサービス中心の構成、モデレーションの自動化（新規ユーザー制限など） |
| 広告を控えめにすると収益が不足する | 事業継続が難しい | 有料プランの価値を練習機能で明確にする。広告単価の高い枠を少数に絞る |

## 9. 用語

| 用語 | 意味 |
|---|---|
| カポ | ギターのフレットを押さえて音程を上げる器具。カポを使うと押さえやすいコード形で弾ける |
| 簡単コード | カポや置き換えで、押さえにくいコード（F などのバレーコード）を減らした表記 |
| 音源同期スクロール | 動画・音源の再生位置に合わせて、譜面の現在位置を自動で追いかける機能 |
| ChordPro | コード譜をテキストで書くための広く使われている記法（例: `[C]歌詞[G]歌詞`） |
| インタラクティブ配信 | インターネット上でユーザーの求めに応じて著作物を送信すること。歌詞掲載はこれにあたる |
